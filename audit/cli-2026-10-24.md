# Qualification du CLI et des corrections natives — 24 octobre 2026

## Corrections

- L’assistant transmet au parseur Transformers le préfixe exact du prompt,
  décodé avec les tokens spéciaux. Il conserve uniquement les réponses finales
  réussies dans l’historique partagé avec le CLI. Une réponse vide ou une erreur
  du moteur produit un échec explicite de la commande.
- La case de suivi et le choix d’algorithme appliquent immédiatement leur état.
  L’interface indique le suivi actif, suspendu, demandé ou incompatible avec SAM,
  et affiche le nombre d’identifiants. Les identifiants sont lisibles par le CLI.
- Avant le chargement de l’assistant, les modèles inactifs du cache sont libérés
  et leurs références cycliques collectées. Un test vérifie cette libération
  avant l’allocation des poids, tout en conservant le détecteur actif.
- Une capture CLI utilise l’image brute actuelle si l’annotation est périmée.
  Une capture d’apprentissage ratée ne réduit plus le nombre d’échantillons restant.

Le contrat du parseur est documenté dans la
[documentation officielle Transformers](https://huggingface.co/docs/transformers/en/chat_response_parsing).

## Couverture automatisée

La suite complète donne **112 tests réussis et 2 tests Linux ignorés sous Windows**.
Ruff et `pip check` réussissent.

`tests/test_cli.py` exécute les **38 commandes annoncées**, chacune dans un vrai
sous-processus CLI, par HTTP authentifié, la boucle Qt et le worker natif.
Une assertion compare les commandes exercées au catalogue pour empêcher qu’une
fonctionnalité ajoutée échappe silencieusement à cette couverture.

Les frontières caméra, modèles ML et SMTP sont simulées dans cette suite.
La validation, les tâches, le chiffrement et les écritures de configuration,
les captures PNG, le démarrage/arrêt et la synchronisation des widgets sont réels.
Les essais couvrent aussi les échecs, un historique non pollué, les mots de passe
refusés dans les arguments, les paramètres invalides sans réaffichage de leur
contenu, l’authentification, la file bornée, les délais dépassés et les contrôles
d’aperçu disponibles pendant une opération longue.

## Qualification matérielle depuis le CLI

Essais sur le flux réel, avec GPU CUDA et données de qualification isolées.

| Fonction | Résultat observé |
| --- | --- |
| Caméra | Lecture, modification puis restauration des réglages ; reconnexion et redémarrage de l’encodeur ; nouvelles images reçues |
| Profils | Lecture masquée et privée, activation, sauvegarde du profil existant et découverte Tailscale |
| Détection | Activation/désactivation, confiance, classes et chargement YOLO TensorRT |
| Segmentation YOLO | Moteur de segmentation chargé et traitement du flux vérifié |
| Export TensorRT | Export FP16 d’une copie de modèle de test réussi en environ 268 secondes ; modèles existants préservés |
| Suivi | ByteTrack a fourni un identifiant commun à deux observations ; passage à BoT-SORT réussi |
| SAM2 | Inférence sur le flux confirmée, indépendamment du succès du chargement |
| SAM3 | Inférence fraîche confirmée avec 7 régions ; concepts modifiés puis retour au détecteur |
| Visages | Modèles prêts, import d’une photo et reconstruction effective d’une galerie isolée |
| Animaux | Modèle DINO prêt, import d’une image de chats et reconstruction effective d’une galerie isolée |
| Apprentissage | Démarrage, compteurs et arrêt vérifiés pour les deux galeries ; collecte complète non qualifiée faute de sujet correspondant présent pendant l’essai |
| Assistant | Deux réponses françaises réussies sur l’image courante ; historique de quatre messages ; environ 39,5 secondes avec chargement puis 3,9 secondes pour la seconde question |
| Aperçu et fichiers | Pause, annotations, plein écran, capture PNG, journal et consultation des tâches |
| Alertes | Configuration factice chiffrée et validation sans envoi ; envoi et activation testés uniquement avec SMTP simulé |
| Cycle de vie | Arrêt propre de l’instance isolée et relance de l’application normale par le CLI |

Les durées sont des observations de cette session, pas un benchmark garanti.
Le premier essai de l’assistant a dépassé le délai CLI de 240 secondes, puis
terminé correctement : son résultat a été récupéré avec `job.get`, sans
soumettre une seconde génération. Le dernier essai ci-dessus utilise le code
avec libération du cache. Les modèles lents restent soumis aux ressources GPU.
Ces essais valident les opérations ; ils ne mesurent pas la précision biométrique
ou la qualité générale des modèles.

L’image animale de test provient de la
[fixture publique Transformers](https://github.com/huggingface/transformers/blob/main/tests/fixtures/tests_samples/COCO/000000039769.png).

## Préservation et confidentialité

Aucun email réel n’a été envoyé. Les galeries et identifiants de test utilisent
un dossier séparé. Après arrêt des essais, la configuration originale a été
rétablie à l’octet près et les empreintes des **584 fichiers privés protégés**
ont été vérifiées : aucun fichier modifié et aucune photo supplémentaire dans
les galeries d’origine. Les réglages vidéo d’origine ont été restaurés.

Le contrôle HTTP écoute seulement sur la boucle locale et exige un secret
aléatoire dans un descripteur ignoré par Git. Les paramètres des tâches sont
exclus des réponses et retirés après exécution. Les sorties susceptibles de
révéler des appareils, adresses ou conversations restent privées ; aucun journal
brut, descripteur, capture réelle, identifiant réseau ou email personnel
n’accompagne ce rapport.

Utilisation et contrat complet : [guide CLI](../docs/cli.md).
